Gstore 0.0.4

19 October 2026 · previous release 0.0.3, the same day

A small packaging release. It fixed the download links, put the right version number inside the built applications, and replaced the placeholder app icon with the real artwork. Nothing about how Gstore itself behaves changed.

Download links that stay put

Release assets had carried the version in their filename — Gstore-0.0.3-windows-x64.zip, and a DMG whose name varied with the architecture it was built on. Every new release therefore broke every link that pointed at the last one, so nothing could link to "the current download" and keep working.

Assets now use fixed names:

Gstore-macos-arm64.dmg
Gstore-macos-intel.dmg
Gstore-windows-x64.zip

which makes GitHub's permanent redirect usable, and that is what the README and the site have pointed at ever since: 

https://github.com/Parthivsurya/Gstorage/releases/latest/download/Gstore-macos-arm64.dmg

Correct version metadata in the bundles

The macOS bundle's version was written separately from the package's, so the two could disagree — and had. The build now reads gstore.__version__ directly, so Get Info on the application and the version the app reports are the same number by construction.

The real app icon

Until this release the icon was a placeholder drawn programmatically at build time. 0.0.4 replaced it with the designed artwork, which also became the source for the Google sign-in consent screen's logo.

Upgrading

Nothing to do. No change to the local index, to linked accounts, or to stored files. Replacing the application is enough.

Consider going straight to 0.1.0. It is a far larger release: transfers run several chunks at a time, interrupted transfers resume in both directions, a dropped connection no longer ends a transfer, and there are Linux builds. Read the 0.1.0 notes.
