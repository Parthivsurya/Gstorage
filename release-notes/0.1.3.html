Gstore 0.1.3

28 October 2026 · previous release 0.1.2, the same day

A fix for sharing. In 0.1.2, opening a link to a file larger than about 100 MB failed every time. Everything else is unchanged.

Shared files over 100 MB now open

Opening a link to a large file reported: 

Google returned a web page instead of file data —
the share may have been withdrawn or rate limited

Nothing was withdrawn and nothing was rate limited. Google Drive does not virus-scan files over roughly 100 MB, and instead of the file it serves a confirmation page asking whether you want to download it anyway — as a web page, with a success code. Gstore saw markup where it expected bytes, and said so in the only terms it had.

The mistaken assumption was that no shared piece could be that large. Gstore splits a file across accounts only when it fits in no single one of them; a file that fits is stored whole, at whatever size it happens to be. So a 20 GB file — stored as 409 pieces of 50 MB — shared perfectly well, while a single 130 MB file did not.

Gstore now follows the confirmation the page asks for and downloads the file. A page that carries no such confirmation is still reported as unavailable, because that genuinely is a withdrawn or rate-limited share.

Both ends need 0.1.3. Sharing was never the broken half — links created by 0.1.2 are perfectly valid. It is opening one that failed, so whoever receives a link needs this version. Links already sent keep working; the recipient just needs to update.

No Intel macOS download

The site and README offered a macOS Intel build. No release has ever actually carried one — the runner that job needs is rarely available — so that link had always led to a missing file. It has been removed rather than left to disappoint. The macOS build is Apple silicon only.

Upgrading

Replace the application. Nothing changes in the local index, in linked accounts, or in files already stored or shared.
