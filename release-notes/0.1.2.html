Gstore 0.1.2

28 October 2026 · previous release 0.1.0, 24 October 2026

Two things: a stored file can now be shared by link, and the in-app update check has been fixed — it had never worked in a shipped build.

Share a file by link

Share on the Files tab turns a stored file into a link that anyone can download it with. The person you send it to needs Gstore, and nothing else: no Gstore account, no Google account, no sign-in, and none of your accounts linked on their machine.

That works because every piece of a Gstore file is an ordinary Drive file the app created, so the narrow drive.file permission is enough to mark one readable by anyone holding its identifier. The recipient then fetches it over a plain web request with no token at all. No broader Drive access is involved on either side.

The link does not list the pieces. A 20 GB file is 409 of them, and naming them costs about 26 KB — far past what fits in a message. So the list is itself uploaded to Drive as a small file, encrypted, and the link points at that: 

https://gstore.iampkb.dev/s/#<manifest-id>.<key>

Two things follow from the shape of that URL:

  • Everything identifying sits after the #. Browsers never send that part of a URL to a website, so the page it resolves to — a static page explaining how to open the link — never learns which file is being shared. There is no server in this feature at all.
  • The list is encrypted, and the key exists only in the link. Reaching the manifest without the link yields ciphertext, so the piece identifiers stay unknown. That protects the identifiers, not the bytes: anyone you send the link to can read the file and pass that on.

Stop sharing makes every piece private again and deletes the list, so the link stops working. Like any share link, it cannot recall a copy somebody already downloaded.

Received files are verified the way downloads always have been: each piece against its own checksum as it streams, then the whole file against the sender’s, before the destination file appears. That matters more here than elsewhere, because an unauthenticated Drive endpoint answers a withdrawn or rate-limited share with a web page and a 200 rather than an error.

Sharing is off until you use it. Nothing of yours becomes reachable by anyone else unless you share a specific file. The privacy policy describes exactly what a share does.

The update check now works

Every build so far has failed this check on every launch, silently. The log recorded it and nothing else did: 

gstore.update: update check did not complete: URLError:
  <urlopen error [SSL: CERTIFICATE_VERIFY_FAILED]
   unable to get local issuer certificate>

There was no certificate store for Python to fall back on. A framework Python on macOS needs one installed by hand, and a packaged application carries no system store at all, so the shipped app could never have had one. The Google API calls hid the problem completely — the library they use ships its own certificates and never consults the system’s — so uploads and downloads were unaffected and nothing ever looked wrong.

Gstore now carries its own certificate bundle. It is verified in the packaged build, not just from source, because the broken path only ever appeared once the app was packaged.

If you are on 0.1.0 or earlier, this release cannot notify you. Your copy holds the broken check, so it will never report a new version — including this one. From 0.1.2 onward the notice works normally.

Upgrading

Replace the application. The local index is upgraded automatically on first launch, and an older build still opens an index this version has touched, so going back is possible if you need to. Linked accounts, stored files and in-progress transfers are unaffected.

Under the hood

  • Share links are recorded locally, so a share can be withdrawn later. That record is the only thing that knows the manifest’s identifier once the link has been handed out — if you are removing Gstore entirely, stop sharing first.
  • Permission changes for a split file run several at a time; a 409-piece file is 409 of them.
  • The test suite is up from 190 to 269. The share mechanism was proven end to end against real Drive — shared, downloaded byte-exact with no credentials, then withdrawn and confirmed no longer readable — before any of it was wired to a button.
