Gstore 0.1.7

28 November 2026 · previous release 0.1.6, 26 November

Gstore installs its own updates.

One press, start to finish

0.1.6 learned to fetch an update and check it. This one finishes the job: press Download on the update notice and Gstore fetches the build for your machine, verifies its signature, quits, replaces itself and starts again.

No releases page, no choosing between three files, and nothing to drag into Applications.

And no warning from the operating system

Gatekeeper and SmartScreen trigger on a mark that browsers attach to downloaded files. A file an application fetched for itself does not carry one, so an update installed this way raises no prompt at all.

That is also why Gstore signs its releases and refuses anything that does not match its key. With the operating system stepping out of the way, the signature is what stands in its place. It is still not a code signing certificate, and the first copy you install by hand will still be questioned.

What happens if it goes wrong

The installed copy is moved aside and only deleted once the replacement is in place. If the swap fails, the old version goes straight back. Being left on an older version is an inconvenience; being left with no application is not, and the order of operations exists to make the second impossible.

Your accounts, files, shares and the index that maps them live in Gstore's application-data directory, never inside the app itself, so none of this touches them.

When it cannot

If Gstore is running from source, or installed somewhere you do not have permission to write, it says so plainly and shows you the downloaded file instead of failing partway.

Upgrading

This one you still install by hand — 0.1.6 and earlier can download an update but not apply it. It is the last time.
