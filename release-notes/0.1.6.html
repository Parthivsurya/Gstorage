Gstore 0.1.6

26 November 2026 · previous release 0.1.5, the same day

Updating is one button, and every release is now signed.

One button

When a newer version exists, Gstore has always shown a notice. Pressing Download on it used to open your browser and leave you on the releases page to work out which of three files you wanted.

It now fetches the build for your machine itself, checks it, and shows you the file. There is no choosing, and no way to end up with the wrong one — an Intel Mac is told plainly that no build exists for it, rather than handed a download that cannot run.

Releases are signed

Every download is published alongside a signature made with Gstore's release key, and the app refuses anything that does not match the key built into it. A download that fails the check is discarded rather than saved, and you are told why.

This is not a code signing certificate, and your operating system will still warn you on first launch. Those are different things. A certificate proves an identity to macOS or Windows; this proves to Gstore that a file is the one that was built here. That is the part that matters for an update the app fetches on your behalf, because nothing else is vetting it.

Nothing is installed for you

The verified file is saved into an updates folder inside Gstore's application-data directory and revealed in your file manager. Opening it is still your move. Replacing a running application is a separate job, and doing it badly leaves somebody with no working app, so it is not something to rush.

Privacy

The privacy policy now describes exactly what is requested and when: two unauthenticated requests to GitHub, only when you press Download, carrying nothing about you or your files. Turning the update check off still means nothing is downloaded at all.

Upgrading

Replace the application. Nothing changes in the local index, in linked accounts, or in files already stored or shared. Because 0.1.5 and earlier have no in-app download, this is the last update you fetch by hand.
